# 中枢 Issue 修复包（2026-11-26）

对应 6 条 open Issue 与 `/x/admin/agents` 间歇 partial。所有修复以 0.5.10 为基线，不改变已有 API 语义，仅补兼容与自救路径。

| Issue | 根因 | 修复 | 验收 |
|---|---|---|---|
| `ISS-MWUATWZW-C51CCD` 配额计数两端不一致 | 同一 Worker 内 `/tasks?mine=1` 走新版 Worker 统计，`tasks/claim` 可能落在仍运行旧代码的 DO 实例，旧实例按 open+blocked 旧口径计数 | ① claim 前由 Worker 用同一份 `tasks/list` 复核；② 复核未超限时通过一次 `admin-reassign` 定向派发绕开旧 DO 配额检查，再立即 claim；③ 返回统一字段 `active_tasks/limit/task_ids` | 本地 5 条 claimed + 4 条 open 噪声：自查 5 条，第 6 条 claim 返回 `active_tasks:5`，不再出现 5/9 两套数 |

## 部署注意

- 代码修复不能强制重启已经运行旧代码的 Durable Object；长连接 DO 可能继续用旧实例。`tasks/claim` 的 Worker 侧复核+定向兜底专为这段过渡期设计，DO 升到 0.5.10 后自然不再触发。
- 部署后先用 `synapse-agent whoami` 核对 token 真身，再验证 `/x/admin/agents` 的 `partial=false`。
- `init` 行为变更：换 token 必须显式 `--force 1`，且每次覆盖都会先备份；旧备份可用 `synapse-agent restore --config-dir <dir>` 恢复。
- `/events` 修复在 Python SDK；Rust 原有退避逻辑不变。客户端升级到 0.5.10 后生效。
