# Synapse 第二轮审计与修复（2026-11-19）

线上版本：`68276975-ea6a-43e6-a372-8509042bf9d5`
二进制：`synapse-agent 0.5.1`，R2 `bin/synapse-agent-x86_64-linux-musl`
SHA-256：`e68a3443680fb8bdecc5275ed227e6e0c7aa6dc7ff2caa654757573d7ba200c0`

本轮不是只按清单打勾，而是把“清单已修”的路径重新打了一遍，结果又挖出 6 个真实故障（其中 2 个会让整套会话/安装直接不可用）。

## 一、本轮新发现并修复

| 编号 | 严重度 | 问题（真实表现） | 修复 | 实测 |
|---|---|---|---|---|
| R2-1 | 严重 | 会话 cookie 加了 epoch 后字段顺序写反：`makeSession` 发 `v2.exp.who.ep.sig`，`readSession` 按 `v2.exp.who.sig.ep` 解，签名永远不匹配 → 所有带 cookie 的浏览器请求 403 | 按实际 5 段顺序解，签名固定最后一段；旧 4 段格式仍兼容 | `/auth/login` 拿 cookie 后 `GET /x/admin/stats` 200；伪造跨站 Origin 写操作 403 `csrf_blocked`，同源 200 |
| R2-2 | 高 | DO `claim` 不校验 `t.to`：任何有 publish 权限的 agent 都能抢定向给别人的任务 | `if (t.to && t.to !== b.agent_id) 403 not_your_task` | client 抢 `T-ghost-1`（to=ghost-agent）→ 403；定向给 client 的任务 claim 200，release 后状态 done |
| R2-3 | 中 | `tasks/list` 默认 scope 是 publish，普通 agent 能拉全项目任务台账 | 改为 `admin` scope | 普通 agent → 403 `insufficient_scope: 需要 admin` |
| R2-4 | 中 | `dedupe_key` 全局命名：A 先占用同一 key，B 的同 key 消息被误判重复丢失 | 改成 `dedupe:${sender}:${key}`（append 与 publish 查询两处同步） | A、B 同 key 分别得到 seq 1、2 |
| R2-5 | 中 | 限流“先 COUNT 再写”非原子；并发可绕过 | worker 把 `max_per_min` 注入 publish，DO 内 `rate:${who}:${minute}` 原子计数 | 限额 3 时 10 并发精确 3×200、7×429；随后恢复 60 |

| R2-8 | 高 | `/sdk/manifest` 里 sha 是硬编码旧值；Rust `upgrade` 拿它校验会拒绝真正的新包 | manifest 从 R2 对象实算 sha 并写回元数据 | manifest 返回值与 `/dl/*.sha256` 一致（`e68a3443…`） |
| R2-9 | 严重 | Rust `init`/`status` 未实现：`init` 直接落进运行循环；且从不读 `~/.synapse-agent/config.json`，装完只会拿默认 endpoint/token 空转 | 补 `init`（写 600 配置）、`status`；`Cfg::from_args` 改为“命令行 > 配置文件 > 默认” | `init` 返回并写 600 配置；`status` 读出 endpoint/project/agent/cursor；`run` 用心跳 30s 连上 |
| R2-10 | 中 | Rust `poll_once` 只取最新一条并“游标追平”，积压任务被静默丢弃；自己的 ack 被当消息回收 | 返回最早一条、下轮继续；过滤自己的 ack/自广播；主轮询逐条 ack | 连发两条 backlog：`wait` 依次返回 seq16、seq17（并提示“还有 1 条积压”），不再跳条 |

## 二、攻击面复核（本轮实测）

- **未认证读取**：`/p/{p}/profile`、`/inbox`、`/wsstat`、`/tasks/list` 均 401；`/x/admin/*` 403；无项目名/配额/消息泄漏。
- **水平越权**：yanshi token 访问 `/p/other/artifact/<sha>` → 401；`inbox?agent=*` 只回广播，定向给 ghost 的 seq3 不可见。
- **垂直越权**：普通 agent `tasks/list` → 403；授予 `py-probe` admin 后可读任务台账，收回后立即 403，旧 admin token 401（重签即废）。
- **身份伪造**：heartbeat body 填 `agent_id=ghost-agent`，名册仍只有 `doubao-client`；submission body 填 `agent_id=doubao-client`，落库为 `admin-cli`。
- **WS 票据**：同一 ticket 首次 101、复用 401；拿 yanshi 的 ticket 连 `/p/other/ws` 401。
- **CSRF**：`hub_sess` cookie + `Origin: https://evil.example` 写操作 → 403 `csrf_blocked`；同源 → 200。
- **路径穿越**：`/dl/../worker` 404、`%2e%2e%2f` 400、`a%2fb` 400。
- **XSS**：`api()` 统一 `deepEsc`；此前 jsdom 实测恶意 `agent_id=<img onerror>` 只出现转义文本、0 个 img、无脚本执行。
- **SQL**：D1 全部 prepared statement，无字符串拼 SQL 命中。
- **Cookie**：`HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=28800`；token 不落 localStorage。
- **配额**：`max_agents` 409（`agent_quota_exceeded:25/2` 实测）、`max_storage_mb` 413、`max_msgs_per_min` 429。
- **信息泄露**：服务器错误统一 `{error}`，未回显堆栈/SQL/内部路径；`/dl` 只回显公开哈希。

## 三、三语言 SDK 一致性

协议层（心跳、游标/epoch、inbox、ack、publish、report、artifact、WS 票据、长连接→轮询回退）三端一致；本轮把此前不一致的 `init/config/status/upgrade/profile/state_dir` 补齐。

| 能力 | Python | TypeScript | Rust |
|---|---|---|---|
| init + 600 配置 | `python -m synapse init` | `Client.init()` | `synapse-agent init` |
| 心跳/常驻 | `daemon`（WS 优先→轮询） | `runDaemon()` + `Loop` | `run`（WS 优先→轮询，`YANSHI_NO_WS=1` 强制轮询） |
| 拉取/回执 | `poll_inbox/ack` | `pollInbox/ack` | `wait/peek/run` 自动 ack |
| 发布/上报/产物 | `publish/report/upload/submit` | `publish/report/upload/submit` | CLI 侧以 `run`/`get`/`send` 为主（无完整 artifact API） |
| 自检升级 | `update-check` / `upgrade` | `checkUpdate` / `upgrade` | `upgrade --check 1` / `--apply 1` |
| 管理面 | `as_admin()` | `asAdmin()` | `agents/subs/send/broadcast/get` |
| 环境识别 | `profile` | `detectProfile()` | `profile` |

差异（有意保留）：Python/TS 是库 + CLI，Rust 是单二进制 agent 运行时；Rust 不提供 `upload/submit` 的完整对象 API，产物上传仍走 Python/TS 或直接 HTTP。三端 `sdk_version` 已统一 0.5.1。

## 四、实测命令摘要（可复现）

```bash
# 会话 + CSRF
curl -c /tmp/jar -X POST -H 'content-type: application/json' \
  -d "{\"token\":\"$ADMIN\"}" https://synapse.wangda.today/auth/login
curl -b /tmp/jar https://synapse.wangda.today/x/admin/stats            # 200
curl -b /tmp/jar -X POST -H 'origin: https://evil.example' ...         # 403 csrf_blocked

# 任务越权 / 台账
curl -X POST -H "authorization: Bearer $ADMIN" .../x/admin/p/yanshi/tasks -d '{"task_id":"T-ghost-1","to":"ghost-agent"}'
curl -X POST -H "authorization: Bearer $CLIENT" .../p/yanshi/tasks/claim -d '{"task_id":"T-ghost-1"}'  # 403 not_your_task
curl -H "authorization: Bearer $CLIENT" .../p/yanshi/tasks/list                                     # 403

# 原子限流（临时把 max_msgs_per_min 调到 3）
seq 1 10 | xargs -P10 ...   # 3×200 + 7×429

# 安装 E2E（裁剪 PATH，无 python3/cargo）
HOME=/tmp/insthome PATH=/tmp/minbin sh scripts/install.sh \
  --endpoint https://synapse.wangda.today --project yanshi --token "$CLIENT" --agent install-probe
# → sha256 校验通过 → config 600 → synapse-agent --version 0.5.1
```

## 五、仍未做/需知

1. **Windows 预编译包未发布**：`install.ps1` 不再指向假 URL，无 Python 时明确失败；要 Windows 原生二进制需加 `x86_64-pc-windows-msvc` target 交叉构建。
2. **pip 包未确认发布到 PyPI**：无二进制平台走 pip 通道时，需要可访问的包源；脚本已 fail-closed，不会装旧包。
3. Rust `upgrade --apply` 只做了“版本相同 → 不升级”和 SHA 校验路径代码审查；真正替换需在版本落后时灰度验证。
4. 管理端“升级 SDK”是快捷任务广播（`kind=sdk_upgrade`），SDK 自检/升级命令已具备；是否自动执行仍由 agent 侧策略决定。
5. 测试残留：`T-ghost-1` 仍 open（定向给不存在 agent，不会被人认领）；三个 probe agent 建议保留作回归，或由管理台吊销。
